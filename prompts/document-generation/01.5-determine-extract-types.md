# Stage 1.5: Determine Extract Types for Each Section

## When Used
Called by `/api/documents/generate` during extraction phase - ONCE per transcript. Analyzes what types of content are available in this specific transcript for each section.

## Input Variables
- `{{transcriptText}}` - Full text of ONE transcript
- `{{transcriptTitle}}` - Title of this transcript
- `{{outline}}` - Document outline from Stage 1 (all sections with descriptions and key questions)
- `{{documentType}}` - The document type being created

## Expected Output
JSON format mapping section IDs to suggested extract types:
```json
{
  "section_1": {
    "extractTypes": ["founder_quote", "validation_method", "market_insight"],
    "rationale": "Why these types are relevant for this transcript"
  },
  "section_2": {
    "extractTypes": [],
    "rationale": "This transcript has no relevant content for this section"
  }
}
```

## Success Criteria
- Extract types are specific and creative (not generic)
- Types match what's actually available in this transcript
- Empty arrays for sections where transcript has nothing relevant
- Types will guide meaningful content extraction

---

## Prompt

You are analyzing a transcript to determine what types of content can be extracted for each section of a "{{documentType}}".

## This Transcript

**Title:** {{transcriptTitle}}

**Content:**
{{transcriptText}}

## Document Outline

{{outline}}

## Your Task

Read through this transcript and, for each section in the outline, determine what specific types of content you could extract that would be valuable for that section.

**Think creatively and specifically** - don't just use generic types like "quote" or "insight". Think about what TYPE of information this transcript contains that would help answer the section's key questions.

### Examples of Specific Extract Types

Instead of generic types, use specific ones like:

**For startup/business content:**
- `revenue_milestone_with_timeframe` (e.g., "$5K MRR in month 3")
- `tool_recommendation_with_rationale` (why they chose Next.js over alternatives)
- `customer_acquisition_tactic` (specific method for getting users)
- `pricing_strategy_decision` (how they set pricing and why)
- `mistake_with_lesson` (what went wrong and what they learned)
- `before_after_comparison` (what changed after a decision)
- `validation_signal` (evidence of market demand)
- `pivot_story` (when and why they changed direction)

**For technical content:**
- `architecture_decision_rationale`
- `performance_optimization_technique`
- `debugging_story`
- `tech_stack_tradeoff`
- `scaling_challenge_solution`

**For any content:**
- `direct_quote_with_context`
- `step_by_step_process`
- `counterintuitive_insight`
- `numerical_data_point`
- `case_study_example`

### Extract Type Naming Rules

**CRITICAL: Extract type names must follow these strict rules for JSON compatibility:**

- ✅ **ONLY use:** lowercase letters (a-z), numbers (0-9), and underscores (_)
- ❌ **NEVER use:** apostrophes ('), quotes ("), dollar signs ($), hyphens (-), or any special punctuation
- ✅ **Good examples:**
  - `metric_5k_mrr_in_month_3`
  - `founder_quote_about_validation`
  - `tool_recommendation_nextjs_vs_react`
  - `pricing_strategy_9_per_month`
  - `dont_rush_technique` (use "dont" not "don't")

- ❌ **Bad examples (will cause parsing errors):**
  - `metric_$5K_MRR` ← contains $ and uppercase
  - `don't_rush` ← contains apostrophe
  - `founder_quote_"we_knew"` ← contains quotes
  - `tool-recommendation` ← contains hyphen
  - `PricingStrategy` ← contains uppercase

**Why this matters:** Extract type names are embedded in JSON strings. Apostrophes, quotes, and special characters break JSON parsing and will cause the entire extraction process to fail.

### Your Analysis Process

For each section:

1. **Read the section's description and key questions**
2. **Scan the transcript for relevant content**
3. **If relevant content exists:**
   - Identify 3-7 specific extract types that would be valuable
   - Be creative - what types would genuinely help write this section well?
   - Think about the section's questions - what types of extracts would answer them?
4. **If no relevant content exists:**
   - Return empty array for extractTypes
   - Explain briefly why (e.g., "This transcript focuses on marketing; no technical content for this section")

## Important Guidelines

- **Be specific**: "metric_with_timeframe" is better than "data"
- **Be creative**: Invent types that match what's in THIS transcript
- **Be honest**: Empty arrays are fine - not every transcript contributes to every section
- **Be useful**: Think about what a writer would need to craft that section
- **Match the content**: Don't suggest "code_example" if there's no code in the transcript

## Output Format Requirements

**CRITICAL: Your response will be parsed by JSON.parse(). Follow these rules EXACTLY:**

1. **NO markdown formatting** - Do NOT wrap your response in ```json or ``` code blocks
2. **NO trailing commas** - The last item in arrays and objects must NOT have a comma
3. **Properly escape strings** - Use proper JSON string escaping for quotes and special characters
4. **Keep rationales concise** - Each rationale should be 1-2 sentences
5. **Start with { and end with }** - Your response should be ONLY the JSON object, nothing else
6. **Valid JSON only** - Your response must pass JSON.parse() without any errors

Return ONLY valid JSON in exactly this format (note: no code blocks, no trailing commas):

{
  "section_1": {
    "extractTypes": [
      "specific_extract_type_1",
      "specific_extract_type_2",
      "specific_extract_type_3",
      "specific_extract_type_4"
    ],
    "rationale": "Brief explanation of why these types are relevant"
  },
  "section_2": {
    "extractTypes": [],
    "rationale": "No relevant content for this section in this transcript"
  },
  "section_3": {
    "extractTypes": [
      "another_specific_type",
      "yet_another_type"
    ],
    "rationale": "This transcript has excellent examples that support this section"
  }
}

**IMPORTANT:** For each section in the outline, provide an entry with extract types and rationale. Your entire response must be valid JSON that can be directly parsed.
