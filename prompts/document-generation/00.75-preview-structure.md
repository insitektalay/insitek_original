# Stage 0.75: Document Structure Preview

## When Used
Called by `/api/documents/preview-structure` endpoint after all questions are answered, before generation begins. Shows user exactly what will be generated.

## Input Variables
- `{{documentType}}` - The document type being created
- `{{conversationHistory}}` - All Q&A pairs from iterative questions
- `{{transcriptSummaries}}` - Brief summaries of the transcript content
- `{{transcriptCount}}` - Number of transcripts
- `{{pageLength}}` - Target page length (e.g., "5 pages (~3,000 words)" or "Automatic")
- `{{targetWordCount}}` - Target word count (number or "automatic")
- `{{customInstructions}}` - User's additional instructions for the document

## Expected Output
JSON format:
```json
{
  "title": "The Complete Document Title",
  "description": "What this document covers and who it's for",
  "estimatedLength": "8,000-10,000 words",
  "sections": [
    {
      "number": 1,
      "title": "Section Title",
      "description": "What this section will cover (2-3 sentences)",
      "keyTopics": ["Topic 1", "Topic 2", "Topic 3", "Topic 4", "Topic 5"]
    }
  ]
}
```

## Success Criteria
- Title is specific and compelling
- Description clearly states purpose and audience
- Section count matches user requirements (if specified) or 6-10 sections for comprehensive coverage
- Each section has clear focus
- Key topics are specific, not generic
- User can understand exactly what they'll get

## Your Task

Before generating the full document, create a detailed outline showing exactly what you will write. This is the user's last chance to review before committing to a 5-10 minute generation process, so be clear and specific.

### 1. Create a Document Title
- Make it compelling and specific
- Should clearly convey what the document is about
- Examples: "The Complete Indie SaaS Playbook", "Technical Guide to Building at Lightning Speed", "From Zero to Traction: A Founder's Journey"

### 2. Write a Document Description
- 2-3 sentences explaining what this document covers
- Who it's designed for
- What makes it valuable

### 3. Estimate Length
- If a target word count is specified, your estimate should align with that target (within ±10%)
- Otherwise, base it on the content available and the document type
- Typical range: 5,000-15,000 words (if no constraint specified)
- Be realistic given the transcript content

### 4. Design the Section Structure

If custom instructions specify a structure, follow it exactly without adding extras. Otherwise, create 6-10 main sections for comprehensive coverage.

Each section should:
- Have a clear, descriptive title
- Focus on one major aspect/theme
- Be described in 2-3 sentences
- List 3-5 specific key topics that will be covered

Guidelines for section design:
- Sections should flow logically (often: intro concepts to implementation to advanced topics to wrap-up)
- Don't make sections too broad ("Everything About Marketing") or too narrow ("Choosing Button Colors")
- Each section should be substantial enough for 800-1,500 words
- Key topics should be specific (not "growth tactics" but "Reddit launch strategy", "Twitter engagement approach")
- Do not add bonus sections like "Tips", "How to Use", or "Additional Resources" unless the user requested them

### 5. Tailor to User Preferences
- If user wanted "beginner-friendly", sections should build progressively
- If user wanted "technical depth", include implementation details in key topics
- If user wanted to focus on specific aspects, weight sections accordingly

## Before Creating JSON Output

Review the custom instructions one final time. If the user specified what to include, include only those things. If they specified what to exclude, exclude it. If they specified a section count, use that exact number. If they said "only X and Y", create only X and Y.

Follow user instructions precisely. Do not add helpful extras that were not requested.

3. **Properly escape strings** - Use proper JSON string escaping for quotes and special characters
4. **Keep descriptions concise** - Each field should be 2-3 sentences maximum
5. **Start with { and end with }** - Your response should be ONLY the JSON object, nothing else
6. **Valid JSON only** - Your response must pass JSON.parse() without any errors

Return ONLY valid JSON in exactly this format (note: no code blocks, no trailing commas):
