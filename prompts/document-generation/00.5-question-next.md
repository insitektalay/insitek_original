# Stage 0.5: Iterative Question Generation

## When Used
Called by `/api/documents/question-next` endpoint after user selects a document type. Called repeatedly (once per question) until LLM determines it has enough information.

## Input Variables
- `{{documentType}}` - The document type user selected (e.g., "Founder Playbook Blueprint")
- `{{conversationHistory}}` - JSON array of previous Q&A pairs: `[{question: "...", answer: "..."}]`
- `{{transcriptTopics}}` - Brief summary of what the transcripts cover
- `{{customInstructions}}` - User's specific requirements for the document (may be empty)
- `{{analysisSummary}}` - High-level summary of transcript themes from Stage 0 analysis
- `{{structuredFacts}}` - Concrete facts extracted from transcripts (counts, entities, themes, etc.)

## Expected Output
JSON format:
```json
{
  "question": "The next question to ask (or empty string if done)",
  "options": ["Option 1", "Option 2", "Option 3", "Option 4"],
  "isLastQuestion": false
}
```

When ready to stop asking questions:
```json
{
  "question": "",
  "options": [],
  "isLastQuestion": true
}
```

## Success Criteria
- Questions are context-aware (adapt based on previous answers)
- Questions reference structured facts and actual content from transcripts
- Questions don't assume content or quantities that don't exist
- Complete freedom - NO prescribed questions about "audience" or "tone" unless LLM decides they matter
- Natural conversation flow, not a rigid form
- LLM stops when it has enough information (typically 2-4 questions)
- Each question provides meaningful signal for document customization

## Prompt

You are helping create a "{{documentType}}" from transcript content about: {{transcriptTopics}}

{{#if conversationHistory}}
## Previous Conversation

{{#each conversationHistory}}
**Q{{@index+1}}:** {{this.question}}
**A{{@index+1}}:** {{this.answer}}

{{/each}}
{{else}}
This is the first question - you haven't asked anything yet.
{{/if}}

## User's Custom Instructions

{{customInstructions}}

**IMPORTANT:** If the user has provided custom instructions above, you already know what they want. Do NOT ask redundant questions about things they've already specified. Instead, ask complementary questions that build on their requirements. For example, if they said "I want a trader's handbook," don't ask "What should this document be about?" - ask about depth level, specific topics, or format preferences.

## Content Analysis

**Analysis Summary:** {{analysisSummary}}

**Structured Facts from Transcripts:**
```
{{structuredFacts}}
```

**CRITICAL:** These structured facts are GROUND TRUTH from the actual transcript content. When asking questions that involve quantities, scope, or specific items:
- **Reference actual counts** - If there are 5 recipes, ask "You have 5 recipes. How would you like to organize them?" NOT "How many days should each recipe appear?"
- **Use real entities** - If specific people/tools/frameworks are mentioned, reference them in your questions
- **Match scope to content** - Don't ask for a 10-section document if there are only 3 key themes
- **Validate feasibility** - Don't ask questions that assume content that doesn't exist

**Examples:**
- ✅ GOOD: "You have 5 recipes covering Italian cuisine. Should this be organized by meal type, difficulty, or cooking technique?"
- ❌ BAD: "How many days should the 7-day meal plan cover?" (when there are only 5 recipes)
- ✅ GOOD: "The transcripts mention Gordon Ramsay and Thomas Keller. Should we highlight their specific techniques?"
- ❌ BAD: "Which celebrity chefs should we feature?" (without checking who's actually mentioned)

## Your Task

Decide whether to ask another question or whether you have enough information to create an excellent document.

**You have COMPLETE FREEDOM** to ask about anything you think matters for creating this specific document type. Do NOT follow a template or prescribed list. Think about:

- What would genuinely help you customize this document?
- What has the user already told you that informs what to ask next?
- What's actually important for THIS document type specifically?
- Have you gathered enough to proceed?

Examples of questions you MIGHT ask (but only if they make sense for this context):
- "What's your main goal with this document?"
- "What level of detail do you want?"
- "Should this focus more on strategy or tactics?"
- "Who is the intended audience?"
- "What tone would you prefer?"
- "Are there specific aspects you want emphasized?"

But don't feel limited to these - ask what YOU think matters.

## Decision Point

**If you have enough information to create a great {{documentType}}:**
- Set `isLastQuestion: true`
- Leave `question` empty
- Leave `options` empty

This typically happens after 2-4 questions, but use your judgment.

**If you need to ask another question:**
- Set `isLastQuestion: false`
- Write ONE clear question
- Provide 3-4 multiple choice options (the system auto-adds "Other")
- Make sure options are mutually exclusive and cover the likely answers

## Output Format Requirements

**CRITICAL: Your response will be parsed by JSON.parse(). Follow these rules EXACTLY:**

1. **NO markdown formatting** - Do NOT wrap your response in ```json or ``` code blocks
2. **NO trailing commas** - The last item in arrays and objects must NOT have a comma
3. **Properly escape strings** - Use proper JSON string escaping for quotes and special characters
4. **Start with { and end with }** - Your response should be ONLY the JSON object, nothing else
5. **Valid JSON only** - Your response must pass JSON.parse() without any errors

Return ONLY valid JSON in exactly this format (note: no code blocks, no trailing commas):

If asking another question:
{
  "question": "Your next question here",
  "options": ["Option 1", "Option 2", "Option 3", "Option 4"],
  "isLastQuestion": false
}

OR if you're done asking questions:
{
  "question": "",
  "options": [],
  "isLastQuestion": true
}

## Important

- Ask questions ONE AT A TIME - you'll see the answer before deciding what to ask next
- Adapt based on previous answers - if user wants "technical depth", your next question might be about code examples
- DON'T ask unnecessary questions just to hit a number - stop when you have enough
- Each question should provide genuine value for customization
- Your entire response must be valid JSON that can be directly parsed
